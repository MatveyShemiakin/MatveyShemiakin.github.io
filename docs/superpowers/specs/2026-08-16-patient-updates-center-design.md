# Центр обновлений для раздела «Пациентам»

## Цель
Добавить в `/patients/` ненавязчивый механизм уведомления о новых опубликованных материалах без внешних сервисов, регистрации и push-инфраструктуры.

## Утверждённый UX
В шапке раздела `/patients/` появляется компактная кнопка-колокольчик со счётчиком непросмотренных обновлений, например `🔔 2`.

При нажатии открывается панель «Что нового» с последними опубликованными материалами. Для каждого элемента показываются:
- статус `НОВОЕ`, если пользователь ещё не просматривал обновление;
- краткий заголовок;
- короткое описание;
- дата публикации;
- ссылка на материал.

На мобильных устройствах панель разворачивается почти на всю ширину экрана. На desktop — как компактная выпадающая панель из шапки.

## Поведение
- Список обновлений хранится в отдельном статическом JSON-файле сайта.
- Каждый элемент имеет стабильный уникальный `id`, дату, заголовок, описание и URL.
- В браузере сохраняется список просмотренных обновлений через `localStorage`.
- Счётчик в шапке показывает количество элементов, которых нет в локальном списке просмотренных.
- При открытии панели новые элементы визуально выделяются.
- Переход по карточке помечает соответствующее обновление просмотренным.
- Кнопка «Прочитать всё» помечает все текущие обновления просмотренными.
- Если новых элементов нет, колокольчик остаётся доступным, но счётчик скрыт.

## Данные
Предлагаемый файл: `/patients/updates.json`.

Структура элемента:
- `id` — стабильный идентификатор обновления;
- `published` — дата публикации в ISO-формате `YYYY-MM-DD`;
- `title` — короткий заголовок;
- `description` — одно короткое пояснение;
- `url` — относительная ссылка на материал.

В первую версию включаются только реально опубликованные материалы. Статус «готовится» в центр обновлений не попадает.

## Архитектура frontend
Функциональность реализуется на Vanilla JS без внешних библиотек.

Компоненты:
1. `updates.json` — источник данных.
2. JS-модуль внутри существующего пациентского frontend-слоя или отдельный `patients-updates.js` — загрузка данных, вычисление непросмотренных, управление панелью и `localStorage`.
3. CSS-классы в существующих пациентских стилях — оформление колокольчика, бейджа и панели.
4. Минимальная семантическая HTML-разметка в шапке `/patients/` для кнопки и контейнера панели.

Не используются inline-стили.

## Доступность
- Кнопка имеет понятный `aria-label`.
- Состояние панели отражается через `aria-expanded`.
- Панель закрывается по `Escape` и по клику вне неё.
- Навигация по элементам доступна с клавиатуры.
- Счётчик не является единственным способом обозначить наличие новых материалов: используется текстовая метка `НОВОЕ` внутри панели.

## Яндекс Метрика
После согласия пользователя на аналитику отправляются обезличенные события:
- `updates_open` — открыта панель «Что нового»;
- `update_click` — переход к одному из обновлений;
- `updates_mark_read` — пользователь нажал «Прочитать всё».

Текст заголовков, медицинская тематика и иные содержательные параметры в Метрику не передаются.

## Приватность
Механизм не собирает персональные данные и не создаёт серверную учётную запись. Состояние просмотренных обновлений хранится только локально в браузере пользователя.

## Совместимость
Решение должно работать в современных браузерах на desktop и mobile. При недоступном `localStorage` панель продолжает отображать обновления, но состояние прочитанного между сессиями не сохраняется.

## Обновление контента
При публикации нового пациентского раздела добавляется одна запись в `updates.json`. После этого новое обновление автоматически появляется у посетителей раздела `/patients/` и увеличивает счётчик непросмотренных.

## Тестирование
Перед публикацией необходимо проверить:
- загрузку и отображение списка;
- корректный счётчик непросмотренных;
- сохранение просмотренных элементов;
- «Прочитать всё»;
- закрытие панели по `Escape` и клику вне;
- отсутствие ошибок при недоступном `localStorage` или `updates.json`;
- отправку событий Метрики только при аналитическом согласии;
- мобильную и desktop-разметку без визуального нарушения текущей шапки.

## Границы первой версии
Не входят в первую версию:
- Web Push;
- email-рассылки;
- Telegram-бот;
- серверная база подписчиков;
- персонализация обновлений по диагнозам или истории просмотров.
