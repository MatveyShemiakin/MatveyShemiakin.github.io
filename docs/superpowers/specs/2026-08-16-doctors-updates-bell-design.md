# Колокольчик «Что нового» для раздела «Для врачей»

## Цель
Добавить на `/for-doctors/` и `/en/for-doctors/` такой же по поведению индикатор обновлений, как в разделе «Пациентам», но с отдельным врачебным потоком. Каждый новый или существенно обновлённый клинический материал должен автоматически появляться в колокольчике без ручного редактирования списка уведомлений.

## Интерфейс
- Колокольчик размещается в верхней панели раздела «Для врачей» рядом с языковым переключателем.
- Визуальный паттерн, счётчик непрочитанных, панель, бейдж «НОВОЕ», «Прочитать всё», закрытие по Esc/клику вне панели и localStorage повторяют пациентский компонент.
- RU и EN показывают локализованные подписи и ведут на соответствующую языковую версию материала.
- ПК и мобильная версия используют один компонент с адаптивной панелью.
- Светлая/тёмная тема должна сохранять WCAG-контраст.

## Источник данных
Вместо ручного `updates.json` для врачей используется генерируемый файл `for-doctors/updates.json`.

Генератор проходит по опубликованным материалам внутри `for-doctors/*/index.html` и их EN-парам, исключая служебные страницы вроде `professional-use.html` и сам индекс раздела. Для каждого материала он формирует стабильную запись:
- `id` — нормализованный относительный путь материала;
- `published` — дата первого появления в журнале;
- `updated` — дата последнего существенного изменения;
- `title` / `title_en` — H1 или `<title>` соответствующей версии;
- `url` / `url_en` — RU/EN адреса;
- `kind` — `new` или `updated`.

Чтобы обычная техническая инъекция навигации, аналитики или юридических блоков не создавалась как медицинское обновление, генератор считает отпечаток только основного клинического содержимого (`<main>`/контентный контейнер) после удаления общих инфраструктурных элементов. Состояние предыдущих отпечатков хранится в отдельном машинном manifest-файле в репозитории.

## Правило уведомлений
- Новый клинический материал → новая запись `kind: new`.
- Изменился основной клинический текст/структура материала → `kind: updated` с новой датой.
- Изменились только общие стили, навигация, аналитика, юридические вставки, служебные скрипты или footer/header → новое уведомление не создаётся.
- RU/EN не дублируются как две новости: это одна запись с двумя URL/заголовками.
- Старые записи не удаляются автоматически; панель сортируется по дате последнего события, новые сверху.

## Автоматизация
Существующий workflow `Inject legal, analytics and professional modules` получает дополнительный шаг генерации врачебного update-feed до тестов и коммита сгенерированных файлов. Таким образом любое изменение врачебного клинического HTML в `main` автоматически обновляет `for-doctors/updates.json` и manifest.

## Компоненты
- `for-doctors/doctors-updates.js` — UI, read/unread state, RU/EN локализация, аналитические события.
- `for-doctors/doctors-updates.css` — внешний CSS без inline-стилей.
- `scripts/generate_doctors_updates.py` — детектор новых/изменённых материалов и генерация feed/manifest.
- `scripts/inject_doctors_updates.py` — идемпотентно подключает компонент к RU/EN индексам раздела.
- `for-doctors/updates.json` — публичный поток обновлений.
- `for-doctors/updates-manifest.json` — техническое состояние отпечатков и дат публикации.

## Тестирование
- генератор не создаёт событие при повторном запуске без изменений;
- изменение клинического `<main>` создаёт `updated`;
- изменение только header/footer/analytics не создаёт событие;
- RU/EN объединяются в одну запись;
- UI корректно считает непрочитанные и хранит прочитанное независимо от пациентского колокольчика;
- ссылки ведут в нужную языковую версию;
- компонент инъектируется один раз, без inline styles;
- smoke-проверка desktop/mobile и light/dark для `/for-doctors/` и `/en/for-doctors/`.
